# GASF 组会讲稿与口头说明

建议顺序：01 → 02 → 03 → 04 → 04b → 05。每页约 30–60 秒。先说观测结果，再说明目前证据的边界。

## 01 — Online Mask-State Evolution

“上排是三个静态实验，下排是四个运动实验。静态时已经积累候选体素，但这些日志中没有正 Mask；动态时出现了正 Mask。四组首次记录到正 Mask 的 Frame 是 170、140、170 和 50。”

提醒：静态横轴是 0–750，动态是 0–1800；纵轴相同，可以比较体素计数，但不能直接凭屏幕上斜率比较变化速度。点标记是实际观测的稀疏标记，连接线经过全部原始日志点，仅作视觉引导。首次正样本不是精确激活时刻；计数变平不代表 Mask 成员不再变化或已证明收敛。01_static 没有外笼体。

## 02 — Mask Hit Ratio Comparison

“三个静态实验的所有记录均为 0%。运动实验的逐日志样本平均比例，Arc A 为 1.6412%，Loop A 为 1.7059%，Arc B 为 3.1832%，Loop B 为 3.4896%。右边可以看到启动阶段和后续波动。”

公式为 candidate_hits/raw，raw 是全部输入点，不是仅近场点。这是 Mask 命中比例，没有真实自体/环境标签，不能称为 Precision、Recall 或 Accuracy。更高不自动代表更好，可能涉及不同笼体、场景或误删。箱线中间是中位数，不是标题中均值；箱体为 IQR，须为 1.5 IQR。散点只在类别方向抖动，数值没有改动。

## 03 — Runtime Latency Distribution

“843/845 个记录的回调耗时不超过 3.2 ms。右图放大这一区域，便于看主要分布；左图保留全部范围，包含两个超过 3.2 ms 的观测。最大值 9.304 ms 来自 03_arc_A 的 Frame 1500，没有被删掉。”

右图是经验累积分布，分母仍为每组全部记录数，不是把放大范围内的样本重新归一化。843/845 只是合并日志的描述性计数，不是重复试验的总体推断。日志每 10 帧一次，因此这些值、P95/P99 和最大值只属于日志样本，不能给出完整逐帧延迟保证。计时还不包括随后 stats 日志输出或后台学习完成。不同运行的硬件负载与订阅条件未完整记录，不能把组间差异完全归因于运动或算法。

## 04 — Static vs Dynamic Learning

“把学习状态分成两页看。这页先看 Mask 和候选地图。静态实验有候选，但没有记录到正 Mask；运动实验有活跃 Mask，候选和 Mask 数量也会出现下降和波动。”

候选体素是当前 map 大小，不是从开始到结束的累积唯一体素数，也不是与 Mask 互斥的另一类体素。候选清理和异步快照能使计数降低。静态/动态横轴范围不同但纵轴按行一致。A/B 是不同笼体条件，实验长度不一致，也没有已确认的匹配重复试验，不能做因果或显著性结论。

## 04b — Learning Progress and Queue Status

“学习器处理计数随实验推进增长。静态的全局方向分箱为 1–2，运动实验达到更多分箱，并最终碰到实现的 60-bin 上限。七组的 845 个日志观测里，累计 dropped_learning_batches 都为 0。”

Learning frames 是后台处理的 observation batch 数，和接收 Frame 相差 0 或 1 是异步观测，不能直接当成丢帧。队列丢弃计数为零不表示 LiDAR 或 ROS 传输没有丢失。60-bin 平台是实现上限，不代表完整方向覆盖。全局分箱数也不是每个体素满足准入所需的方向位数。

## 05 — Orientation Diversity vs Mask Activation

“左右分别是 Cage A 和 Cage B，上排看 Mask，下排看候选地图。灰色无笼体静态参考在两列重复展示。每个点对应真实记录，60 bins 处的竖向点簇包括全部重叠观测，没有删点或抖动。”

可以描述方向分箱与计数之间的观测关系，但不能说分箱增加导致了所有 Mask 变化：两者共享时间趋势、样本自相关、分箱受上限限制，而且后台状态和 Mask 不是同一时刻的原子快照。04_loop_A 还有 LiDAR/笼体相对位移，星号用于持续提醒。原始 Spearman 表仅作描述，无独立样本显著性检验。

## 可用于结束汇报的一句话

“目前证据支持原型在这些日志中完成在线候选积累与动态条件下的 Mask 建立，并给出毫秒量级的采样回调耗时；真实识别准确率、完整实时保证和收敛性，还需要标注数据、逐帧记录与重复对照实验。”

下一步建议：匹配时长、负载和安装条件的重复冷启动；保存构建/参数清单；完整逐帧和端到端计时；保存 Mask 身份快照并定义稳定判据；独立标注自体/环境点做留出评估。
